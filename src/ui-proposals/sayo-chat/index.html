会話の場所を作る案（A〜C）

案A〜EをTOPページ・リストページに置いたときの見え方は 置き場所の比較（placements.html） で並べて確認できます。

案A

専用ページ「サヨの映画店」

/chat に専用ページを置く。PCは左に立ち絵のカウンター、右に会話。SPは上に立ち絵の帯、下に会話。木目と紙の暖色で、サイト本体と空気を変える。

  • 立ち絵と会話を同時に大きく見せられる
  • 記事カードを横並びで広く出せる
  • 合言葉の入口・注意書き・残り回数を1画面にまとめやすい
  • 専用ページへ来てもらう導線が別に必要
  • 記事を読みながらは使えない

案B

全ページのフローティングウィジェット

右下の顔アイコンから開くパネル。PCは右下に400px、SPは全画面のシート。記事詳細では「この作品についてサヨに聞く」から質問を差し込める。

  • どのページからでも話しかけられ、利用が増えやすい
  • 記事の文脈から質問を始められる
  • サイト本体の配色に溶け込む
  • 立ち絵が小さく、キャラクターの魅力が出にくい
  • 全ページのJSが増える（読み込みは開いた時に遅らせたい）
  • ページを移ると画面の会話が途切れる（保持の仕組みが要る）

案C

ノベル風の舞台

立ち絵を画面いっぱいに置き、名前札つきのウィンドウで返事を1文字ずつ表示。記事カードは「棚から出した作品」として浮かび上がる。過去の会話は履歴ドロワーで読む。

  • キャラクターの存在感がいちばん強い
  • 正式な立ち絵（5表情）が届くと表情の変化が最も活きる
  • 1往復ずつ見せるので、返事が短い人格と相性がよい
  • 過去の返事や記事カードを見返しにくい
  • 1文字表示は読む速さの合わない人もいる（クリックで全文、動きを減らす設定に対応）
  • 全画面の絵の容量が大きい
案Cを開く →

各案の左下（または右上）の「モック操作」で、次の送信を上限・エラー・セッション切れなどに切り替えられます。入力に「ホラー」「泣ける」「裏話」「ネタバレ」「AI」を含めると、それぞれの架空の応答を返します。それ以外は「該当なし」になります。

カードから要約する案（TOPページ・リストページ限定）

TOPページとリストページに限って置く。上部の「何を観ようか迷ったら」で作品を探し（パターン1）、カード（HomeCard／PostCardImgLeft／ImgTop）の「要約」ボタンでサヨが作品を要約する（パターン2）。押した後をモーダルにするか（案D）、専用ページにするか（案E）を、同じカードから切り替えて比べられます。

案D

カード → モーダル

その場で開く。PCは中央、SPは下からのシート。「前の作品／次の作品」で同じ並びの作品を続けて要約できる。下に「サヨにもっと聞く」。

  • 一覧を離れずに次々と見比べられる
  • ページを増やさずに済む（ルーティング・SEOの検討が要らない）
  • 閉じれば元のスクロール位置に戻る
  • 立ち絵は小さい顔アイコンだけ
  • 会話を続けるには狭い（長くなると要約が上に流れる）
  • URLが無いので共有・戻るボタンで開き直せない
案Dを開く →
案E

カード → 専用ページ

/ja/sayo/{記事slug} のようなページへ遷移。立ち絵・作品・要約・続けての会話・同じ一覧のほかの作品を1ページにまとめる。

  • 立ち絵を大きく出せ、サヨの魅力が伝わる
  • 会話を続けても窮屈にならない
  • URLがあるので共有・戻るができる。要約は承認済みなのでSSGにできる
  • 一覧との行き来が増える（「戻る」でスクロール位置の復元が要る）
  • 記事ページと内容が重なるため noindex などの検討が要る
  • ページとテンプレートが1つ増える

サヨへの問いかけは2パターン

1. おすすめを探す（検索）2. 記事を要約する
役割たくさんの記事から、気分や好みに合う作品を探すタイトルや説明文だけでは開かない人に、記事の中身を短く伝えて記事へ誘導する
入口TOP・リストの上部「何を観ようか迷ったら」。候補ボタン（怖すぎないホラー等）と自由入力各カード右上の「要約」ボタン
探す範囲TOPはすべての記事、リストはそのカテゴリ（例：映画）の記事だけ押したカードの1記事
データと費用候補ボタン：承認済み要約の気分タグ（moodTags）で絞り込む＝LLMなし・回数を減らさない
自由入力：/message（LLM＋検索）＝1回ずつ数える		承認済み要約（summarySafe・recommendFor・moodTags）＝LLMなし・回数を減らさない
「もっと聞く」から先だけLLM
つながり結果の各作品の「要約を聞く」→ 2へ「似た作品は？」→ 他作品の要約へ。モーダルでは「← 結果に戻る」で1へ戻れる
必要なAPI追加気分タグ・カテゴリで記事を返すAPI（元データは facets.json の moodTags）。自由入力のカテゴリ絞り込みも要検討GET /api/chat/articles/{id}/summary
項目案D・案E 共通の考え方
要約の出どころai-chat の索引構築が記事ごとに作り、人が承認した summarySafe（ネタバレなし・300字以内）・moodTags・recommendFor をそのまま出す。LLMを呼ばないので即時・費用0・回数を消費しない
必要なAPI追加ai-chat に GET /api/chat/articles/{id}/summary（記事IDで要約を返す）を追加。いまの /message は自由文だけで、作品名で頼んでも検索に外れる可能性がある。Schemaを先に更新する
もっと聞くここから従来の /message（LLM・1回ずつ数える）。記事を指定して聞けるよう MessageRequest に articleId を足す案も検討
ボタンの置き方カードは全体がリンクなので、ボタンはリンクの「中」ではなく「隣」に置き、画像の上に重ねる（<a> の中に <button> は置けない）。HomeCard／PostCardImgTop の構造変更が要る
ボタンの位置TOPのHomeCardは右上（左上はスコア、右下はVOD）。リストは右上、先頭のリード記事だけ「サヨに要約してもらう」と文字を長く。SPのグリッドは顔アイコンのみ

項目画面の扱い根拠

表情の切り替え（フロントで決める案）

表情出す場面
default挨拶、記事カードのない返事
thinking送信してから応答が来るまで
recommend記事カードが1件以上ある返事
sorryno_match、上限、エラーなど ok 以外
secretspoiler: true の返事

API は表情を返さないため、上の対応をフロントに置く想定です。モックでは画像が1枚なので、拡大・色味の変化と右上の表情名で切り替えを示しています。

決めてほしいこと

  1. どの案を軸にするか（例：B のウィジェットから A の専用ページへ「大きく開く」組み合わせも可能）
  2. ページを移ったり再読み込みしたりしたとき、画面の会話を残すか（API に履歴取得はなく、残すならブラウザ側で保持する）
  3. 限定公開の入口：参加URLのクエリで合言葉を渡すか、入力欄を出すか（案Aに入力欄の例あり）
  4. ネタバレの見せ方：伏せて「表示する」（A）／確認してから出す（B）／ラベルだけ（C）
