# i18n 設計プロンプト（KatsumaScore）

## ■ 目的
コンポーネント単位のi18nから開始し、将来的にグローバル統合可能な設計を行う。

---

## ■ フェーズ1（現行）

### ルール
- i18nは各コンポーネント内に閉じる
- messagesはコンポーネント配下の i18n.ts に定義
- keyはUI構造ベース（意味で命名しない）
- path配列でアクセスする（string直書き禁止）

---

## ■ フェーズ2（検知）

### 共通文言の抽出
- 「検索」「続きを読む」「配信一覧」など頻出語を検出
- 重複は許容するがログ or ESLintで警告

---

## ■ フェーズ3（昇格）

### Design Token化
- 頻出語を global i18n に昇格
- 例：
{
  "common": {
    "search": { "ja": "検索", "en": "Search" }
  }
}

---

## ■ フェーズ4（統合）

### Global i18n
- /src/i18n/messages.ts に統合
- コンポーネントは local → global の順で参照

---

## ■ ESLintルール

### 目的
- 文字列直書き禁止
- i18n経由を強制

### 例
- "検索" → ❌
- t(['common','search']) → ✅

---

## ■ Storybook検証

### 必須対応
- locale切替（ja / en）
- 翻訳漏れ検知

### 検知方法
- missing key → console.warn
- UI上で fallback 表示

---

## ■ 最終方針

- 初期は分散（コンポーネント単位）
- 問題を観測
- 共通化は後から行う

---

## ■ 原則

i18nは「設計しすぎない」
実際の使用頻度から最適化する
